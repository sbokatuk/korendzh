# Роли и права доступа

## Краткое описание ролей

- **Worker** — рядовой сотрудник, отчитывается о рабочем времени.
- **Manager** — руководитель подразделения, ведёт учёт по своей команде.
- **Admin** — администратор организации, видит и управляет всем.

## Матрица прав

Легенда: ✅ — есть доступ, ⚠️ — ограниченный (см. примечания), ❌ — нет.

| Действие | Worker | Manager | Admin |
|---|:---:|:---:|:---:|
| Войти в систему (web/mobile) | ✅ | ✅ | ✅ |
| Создать свою запись TimeEntry | ✅ | ✅ | ✅ |
| Посмотреть свои TimeEntry | ✅ | ✅ | ✅ |
| Редактировать свои TimeEntry | ⚠️¹ | ✅ | ✅ |
| Посмотреть TimeEntry чужого воркера | ❌ | ⚠️² | ✅ |
| Редактировать TimeEntry чужого воркера | ❌ | ⚠️² | ✅ |
| Создать TimeEntry от имени другого воркера | ❌ | ⚠️² | ✅ |
| Добавить автомобиль в справочник | ✅ | ✅ | ✅ |
| Редактировать справочник автомобилей | ❌ | ✅ | ✅ |
| Создать / отредактировать воркера | ❌ | ⚠️² | ✅ |
| Создать / отредактировать менеджера | ❌ | ❌ | ✅ |
| Назначить воркера в подразделение | ❌ | ⚠️² | ✅ |
| Видеть статистику по своему подразделению | ❌ | ✅ | ✅ |
| Видеть статистику по всей организации | ❌ | ❌ | ✅ |
| Видеть визуализированную статистику (графики) | ❌ | ⚠️³ | ✅ |
| Экспорт статистики в Excel/CSV | ❌ | ✅ | ✅ |
| Просмотр audit log | ❌ | ❌ | ✅ |

### Примечания

¹ **Worker и собственные записи.** Правила правки своих записей задним числом уточняются (например, можно ли редактировать запись после того, как менеджер её утвердил, или после закрытия отчётного периода). На текущем этапе по умолчанию — можно, без ограничений.

² **Manager — только своё подразделение.** Все «чужие» действия менеджера разрешены только в пределах его division. Менеджер не видит и не трогает чужие подразделения.

³ **Визуализация для менеджера.** Менеджер видит графики и таблицы по своему подразделению; админ видит то же самое плюс сравнительные графики между подразделениями.

## Аутентификация

Все три роли логинятся одинаково:

- Email + пароль.
- Через Google (OAuth 2.0).

Различие — только в наборе прав после входа. Роль определяется в БД, клиент (веб или мобайл) рендерит интерфейс на основании роли, бэкенд проверяет права на каждый запрос (не доверяя клиенту).
