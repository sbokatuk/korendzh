# Юзеркейсы

Полный перечень пользовательских сценариев с разбивкой по ролям. Каждый кейс имеет идентификатор для трассировки в задачах и тестах.

Связанные документы: [system-overview.md](./system-overview.md), [roles-permissions.md](./roles-permissions.md), [data-model.md](./data-model.md), [validation.md](./validation.md), [notifications.md](./notifications.md).

## Принятые архитектурные решения

- Часы учитываются **сразу** при создании записи. Workflow подтверждения нет.
- Мобильное приложение работает **только онлайн**.
- Уведомления: email + push (детали — [notifications.md](./notifications.md)).
- Первый админ создаётся **сидингом БД** при деплое; дальше админ заводит менеджеров через email-инвайт.

## Worker (Воркер)

### US-W1. Принять email-приглашение и задать пароль
Воркер получает email от менеджера со ссылкой-инвайтом. Переходит, задаёт пароль, попадает в систему. Токен инвайта одноразовый и истекает (см. [data-model.md](./data-model.md)).

### US-W2. Войти по email + пароль
Стандартный логин в веб или мобильном приложении.

### US-W3. Войти через Google
OAuth 2.0. Если email уже привязан к аккаунту, сессия открывается; если нет — отказ (саморегистрация запрещена).

### US-W4. Восстановить пароль
Запрашивает email-ссылку для сброса. Получает письмо, переходит, задаёт новый пароль. Токен одноразовый, истекает быстро (см. [data-model.md](./data-model.md)).

### US-W5. Выйти из системы
Завершает сессию (на текущем устройстве). На мобильном дополнительно сбрасывается push-токен.

### US-W6. Создать запись о рабочих часах
Открывает форму, заполняет: дата, часы, название задачи, автомобиль (с автокомплитом), госномер, краткое описание. Отправляет — запись сохраняется и сразу учитывается в статистике.

### US-W7. Добавить новый автомобиль через автокомплит
В поле «автомобиль» вводит название, которого нет в справочнике. При сохранении записи новый автомобиль создаётся в общем справочнике и доступен другим пользователям.

### US-W8. Посмотреть список своих записей
Видит свои `TimeEntry` с фильтрами: диапазон дат, поиск по названию задачи. Сортировка по дате (по умолчанию — новые сверху).

### US-W9. Отредактировать свою запись
Меняет любые поля своей `TimeEntry`. Изменение фиксируется в audit log.

### US-W10. Удалить свою запись
Может удалить свою запись. Удаление мягкое (soft delete) — запись скрывается из общего вида, но сохраняется в audit log на случай восстановления.

### US-W11. Получить уведомление, если менеджер изменил/удалил запись
Email + push (если установлено мобильное приложение). См. [notifications.md](./notifications.md).

### US-W12. Посмотреть свою личную статистику
Сводка по своим часам за день / неделю / месяц. Не выходит за рамки своих данных.

## Manager (Менеджер)

### US-M1. Принять email-приглашение и задать пароль
Аналогично US-W1, но создаёт его админ.

### US-M2 — US-M5. Логин / Google / сброс пароля / выход
Аналогично US-W2 — US-W5.

### US-M6. Просмотреть список воркеров своего подразделения
Список с фильтром: активные / деактивированные.

### US-M7. Добавить воркера в своё подразделение
Заполняет email и ФИО, выбирает «отправить инвайт» — воркер получает email со ссылкой для установки пароля. Аккаунт создан в статусе «активен, пароль не задан».

### US-M8. Отредактировать воркера
Меняет ФИО / email. При смене email требуется подтверждение нового адреса (опционально — фиксируется на этапе реализации).

### US-M9. Деактивировать / реактивировать воркера
Soft-delete через флаг `IsActive`. Деактивированный воркер не может логиниться, но его исторические `TimeEntry` сохраняются.

### US-M10. Сбросить пароль воркера
Триггерит письмо со ссылкой сброса (как US-W4, но инициировано менеджером).

### US-M11. Просмотреть `TimeEntry` своего подразделения
Фильтры: воркер, диапазон дат, задача, автомобиль. Сортировка и пагинация.

### US-M12. Отредактировать `TimeEntry` любого воркера подразделения
Любые поля. Изменения попадают в audit log; воркер получает уведомление (US-W11).

### US-M13. Удалить `TimeEntry` воркера
Soft-delete. Воркер получает уведомление.

### US-M14. Создать `TimeEntry` от имени воркера
Полезно, если воркер забыл / не имеет доступа. В записи фиксируется `CreatedBy = manager`.

### US-M15. Добавить автомобиль в справочник
Название + (опционально) госномер.

### US-M16. Отредактировать автомобиль в справочнике
Меняет название/госномер. Исторические `TimeEntry` не меняются (см. [data-model.md](./data-model.md)).

### US-M17. Деактивировать автомобиль в справочнике
Скрывает из автокомплита, не ломая историю.

### US-M18. Посмотреть статистику по подразделению
Срезы: часы по воркеру, по задаче, по автомобилю. Период: день / неделя / месяц / произвольный диапазон.

### US-M19. Экспортировать статистику в Excel/CSV
Любой текущий отфильтрованный срез.

## Admin (Администратор)

### US-A1 — US-A5. Логин / приглашение / Google / сброс пароля / выход
Аналогично менеджерским. Первый админ создаётся сидингом БД; дальнейших админов добавляет существующий админ через инвайт.

### US-A6. Управлять менеджерами
Добавлять (с email-инвайтом), редактировать, деактивировать. Один менеджер = одно подразделение.

### US-A7. Управлять подразделениями
Создавать, переименовывать, архивировать. Архивированное подразделение не принимает новые `TimeEntry`, но история сохраняется.

### US-A8. Перепривязать воркера к другому подразделению / менеджеру
Нужно, когда менеджер уходит, либо при реорганизации. Исторические `TimeEntry` остаются на воркере и видны новому менеджеру (для консистентности отчётности).

### US-A9. Добавить нового админа
Через email-инвайт, как менеджера.

### US-A10. Посмотреть и редактировать данные любого подразделения
Те же действия, что у менеджера, но без ограничения по подразделению.

### US-A11. Управлять справочником автомобилей глобально
Включая мерж дублей (опционально, фиксируется на этапе реализации).

### US-A12. Посмотреть визуализированную статистику по всей организации
Графики: сравнение подразделений, динамика во времени, top-N задач/автомобилей.

### US-A13. Экспортировать любую статистику в Excel/CSV

### US-A14. Просмотреть audit log
Кто, когда, что изменил в `TimeEntry` и в пользователях. Фильтры по пользователю, типу события, диапазону дат.

## Системные / технические

### US-S1. Email-доставка
Сервис очереди писем (инвайты, сброс паролей, уведомления об изменении записей). Ретраи при сбое SMTP.

### US-S2. Push-уведомления
APNS (iOS) и FCM (Android). Регистрация push-токена при логине на мобильном; снятие токена при выходе.

### US-S3. Audit log
Каждое создание / изменение / удаление `TimeEntry` пишется в `AuditLog` с before/after-снимком (см. [data-model.md](./data-model.md)).

### US-S4. Истечение токенов
Инвайты — 7 дней (configurable). Сброс пароля — 1 час. По истечении — отказ с пояснением.

### US-S5. Rate limiting на auth-эндпоинтах
Защита от перебора паролей и от спама на запрос сброса.

### US-S6. Бэкап БД
Расписание и retention — на этапе деплоя; фиксируется в [requirements.md](./requirements.md) при развёртывании.

### US-S7. Бэкенд проверяет права на каждый запрос
Клиент (web/mobile) рендерит UI в зависимости от роли, но **никогда не доверяет себе** — все проверки прав на сервере.

### US-S8. Все datetime — UTC в БД, локальные на клиенте
Конвертация по часовому поясу пользователя или браузера.

## Покрытие vs. цели пользователей

| Цель пользователя | Покрытие |
|---|---|
| Воркер быстро отчитывается о часах с поля (мобильное) | ✅ US-W6, форма с автокомплитом и push-уведомлениями |
| Воркер видит, что отправил, и может поправить | ✅ US-W8, US-W9, US-W10 |
| Менеджер видит всю свою команду в одном месте | ✅ US-M11, US-M18 |
| Менеджер быстро правит ошибки воркеров | ✅ US-M12, US-M14 |
| Менеджер забирает данные в Excel | ✅ US-M19 |
| Админ управляет менеджерами и видит всю организацию | ✅ US-A6, US-A10, US-A12 |
| Админ имеет аналитику для принятия решений | ✅ US-A12 |
| Прозрачность: воркер знает, когда его правки меняют | ✅ US-W11 + US-S3 (audit log) |
| Безопасность: только проверенные люди в системе | ✅ Закрытая регистрация (US-W1, US-M1, US-A9) |
