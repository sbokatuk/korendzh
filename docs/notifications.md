# Уведомления

Связано с [user-stories.md](./user-stories.md) (US-W11, US-S1, US-S2) и [data-model.md](./data-model.md) (`NotificationLog`).

## Каналы

- **Email** — для всех ролей. Используется SMTP-провайдер (конкретный сервис фиксируется на этапе деплоя).
- **Push (мобильное)** — APNS для iOS, FCM для Android. Только для пользователей с установленным мобильным приложением и зарегистрированным push-токеном.

Push дополняет email, не заменяет: ключевые события всегда дублируются email-ом, чтобы информация не терялась при отсутствии мобильного у пользователя.

## Матрица событий

| Событие | Кому | Канал | Содержит ссылку | Шаблон-тег |
|---|---|:---:|:---:|---|
| Приглашение нового пользователя | Приглашённый | Email | Ссылка на установку пароля | `invite.created` |
| Запрос на сброс пароля | Пользователь | Email | Ссылка сброса | `password.reset_requested` |
| Пароль успешно изменён | Пользователь | Email | — (информационное) | `password.changed` |
| Менеджер изменил вашу запись | Воркер | Email + Push | Ссылка на запись | `timeentry.edited_by_manager` |
| Менеджер удалил вашу запись | Воркер | Email + Push | Ссылка на список записей | `timeentry.deleted_by_manager` |
| Менеджер создал запись от вашего имени | Воркер | Email + Push | Ссылка на запись | `timeentry.created_by_manager` |

## Важные правила

- **Self-edit не уведомляется.** Если воркер сам редактирует свою запись — push/email не отправляется. Уведомления только когда действие сделал кто-то другой (менеджер или админ).
- **Админ-правки = «менеджер изменил».** С точки зрения воркера, админ-действие неотличимо от менеджерского. Текст письма — нейтральный.
- **Пакетирование.** Если менеджер за короткий период (≤ 5 минут, configurable) изменил несколько записей одного воркера, отправляется одно сводное письмо/push, а не серия. Реализуется на стороне очереди.
- **Идемпотентность.** Каждое отправление пишется в `NotificationLog` с уникальным ключом события — повторная попытка обработки очереди не создаёт дубль.
- **Подписка/отписка.** Email-уведомления об изменении записей пользователь может отключить в настройках профиля. Транзакционные (инвайт, сброс пароля) — нельзя отключить.

## Push-токены

- Регистрируются при логине в мобильном приложении.
- Сохраняются в `User.PushTokens` (или отдельной таблице `PushDevice`).
- Сбрасываются при logout и при ошибке доставки `Unregistered` от провайдера.
- При логине с того же устройства с другим аккаунтом старый токен переписывается на нового пользователя.

## Шаблоны и локализация

- Шаблоны хранятся в репозитории (HTML + plain-text fallback для email; payload для push).
- Язык шаблонов — русский. Мультиязычность — за пределами первой версии.
- В шаблонах нет PII сверх необходимого: ФИО получателя, тип события, ссылка. Никаких сумм / тарифов / персональных данных третьих лиц.

## Транспорт и устойчивость

- Очередь писем (например, через таблицу-аутбокс или брокер) с ретраями: 1 мин, 5 мин, 30 мин, 2 часа, 12 часов. Дальше — `failed`, тревога админу.
- Push-провайдеры (APNS / FCM) опрашиваются с экспоненциальным бэкоффом; при `Unregistered` — токен помечается невалидным.
- Все исходящие уведомления логируются в `NotificationLog` для траблшута.

## SMTP: правильные комбинации порт + режим

Самая частая причина «письма зависают на 120 секунд и таймаутят» — рассинхрон порта и режима TLS:

| Порт | Режим | Когда использовать |
|---|---|---|
| **587** | StartTls (SUBMISSION) | Стандартный режим для отправки. Соединение plaintext, потом upgrade через STARTTLS. Большинство SMTP-провайдеров. |
| **465** | SslOnConnect (SMTPS / implicit TLS) | TLS с первого байта. Старый стандарт. Многие провайдеры (включая `smtp.hoster.by`) поддерживают. |
| **25** | None или StartTls | Только server-to-server передача. Plesk shared-хостинг обычно блокирует исходящий 25 от приложений. Не используем. |

**Совмещать `465 + StartTls` или `587 + SslOnConnect` нельзя** — обе стороны зависнут на чтении и через 120с MailKit кинет `TimeoutException`.

В коде (`SmtpEmailSender`) включён авто-детект: для порта 465 всегда `SslOnConnect`, для 587 — `StartTls`, независимо от значения `UseStartTls` в конфиге. Если конфиг противоречит порту — в логе появится warning «SMTP config mismatch».
