# Валидация и ограничения данных

Все ограничения проверяются **на сервере**. Клиент (web/mobile) дублирует валидацию ради UX, но не является источником истины.

Связано с [data-model.md](./data-model.md) и [user-stories.md](./user-stories.md).

## TimeEntry

| Поле | Правила |
|---|---|
| `WorkDate` | Не обязательно — биндится сегодняшней датой по умолчанию. Допускаются прошедшие и будущие даты (табель может оформляться авансом). |
| `Hours` | **Единственное обязательное поле.** `> 0` и `≤ 24`. Допускаются и точка, и запятая (`1.5` / `1,5`). Серверный парсер мягкий: режет буквы (`8ч`, `8h`, `0.25hr`), пробелы любого вида (включая NBSP) и лишние разделители. Источник истины — сервер (`Create.cshtml.cs` → `TryParseHours`). |
| `TaskName` | Опционально. До 200 символов. Trim пробелов. На UI поле временно скрыто за `<input type="hidden">` (см. `Create.cshtml`). |
| `CarName` | Опционально, до 100 символов. Если введено и нет в справочнике — создаётся новая запись через `CarService.GetOrCreateAsync`. |
| `LicensePlate` | Опционально, до 20 символов. Никаких формат-ограничений (буквы, цифры, дефис, пробел, кириллица — всё проходит). |
| `Description` | Опционально. До 500 символов. |

**Примечание про автомобиль.** Раньше действовало правило «оба поля или ни одного» (XOR-валидация), оно убрано — оказалось основным источником ошибок при сохранении на проде. Сейчас разрешено любое сочетание:

- оба пусты → `CarId = null`;
- только название → запись в справочнике без `LicensePlate`;
- только номер → название берётся равным номеру (чтобы запись попала в справочник и автокомплит её показывал);
- оба заполнены → стандартный кейс.

## User

| Поле | Правила |
|---|---|
| `Email` | Обязательно. Валидный формат. Уникальный в БД. Lowercased при сохранении. IDN-домены (`бокатюк.бел`) хранятся в Punycode (`xn--…`) — нормализация в `EmailNormalizer.ToAscii`. |
| `FullName` | Обязательно. 1–150 символов. |
| `Password` | Минимум 8 символов; должна содержать цифру (см. `DependencyInjection.cs`). Регистр и спецсимволы не требуются. Хранится только хэш. |
| `Role` | Не редактируется через обычный UI. Меняется только админом и только в специальном флоу (например, повышение менеджера до админа). |
| `DivisionId` | Для воркера — обязательно; для менеджера — должно совпадать с `Division.ManagerId`; для админа — `null`. |
| `IsActive` | Единственный способ заблокировать доступ. Деактивацию делает админ из `/Workers` или `/Admin/Managers`. |

**Lockout по неудачным попыткам входа в проекте отключён** — см. [roles-permissions.md → Аутентификация](./roles-permissions.md). Если у юзера в БД с прошлой жизни остались `LockoutEnd` / `AccessFailedCount` — они защитно обнуляются на старте (`DataSeeder.ClearAllLockouts`), при логине (`LoginModel.OnPostAsync`) и при нажатии «Сбросить пароль» в админке.

## Car

| Поле | Правила |
|---|---|
| `Name` | Обязательно. 1–100 символов. |
| `LicensePlate` | Опционально. 1–20 символов. |

Дубликаты по `Name + LicensePlate` не блокируются жёстко (мерж дублей — задача админа в US-A11), но автокомплит сначала показывает существующие записи, чтобы снизить вероятность дубля.

## Division

| Поле | Правила |
|---|---|
| `Name` | Обязательно. Уникальное в системе. 1–100 символов. |
| `ManagerId` | Обязательно для активного подразделения. Один менеджер = одно подразделение. |

## Токены (приглашения, сброс пароля)

| Тип | TTL | Одноразовый |
|---|---|:---:|
| Invite | 7 дней | ✅ |
| Password reset | 1 час | ✅ |

После использования или истечения — токен инвалидируется, повторный логин по нему — отказ.

## Параллельное редактирование

Используется **optimistic concurrency**: при редактировании `TimeEntry` клиент шлёт версию (или `UpdatedAt`), сервер проверяет — если на сервере версия выше, возвращает 409 Conflict с актуальными данными. Клиент показывает «запись изменена кем-то другим, обновите и попробуйте снова».

## Часовые пояса

- Все datetime в БД — UTC.
- `WorkDate` — это локальная дата работы, без времени и без зоны (тип `date`). Воркер выбирает дату в своём календаре.
- Конвертация и отображение — на клиенте.

## Локали и форматы

- Десятичный разделитель в `Hours` — точка `.` на API. В Razor-форме (`/TimeEntries/Create`) сервер принимает оба варианта (`.` и `,`), плюс терпит буквы и пробелы — см. `Create.cshtml.cs → TryParseHours`.
- Дата на API — ISO-8601 (`YYYY-MM-DD` или `YYYY-MM-DDTHH:mm:ssZ`).
